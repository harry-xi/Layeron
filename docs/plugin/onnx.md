# ONNX 模型运行器

`Layeron.Plugins.OnnxRuntime` 插件把 ONNX 模型作为一种**体数据处理方式**接进来：它自己管理一个模型目录，读取每个模型的签名，把会话数据按签名绑定成模型输入，然后把结果变成预览叠加、掩膜层或新的体数据。

::: tip 开箱即用
插件自带两个示例模型（结构增强）。它们内嵌在插件程序集里，运行时直接从内存加载，不写任何文件，所以装完就能跑，不需要先去找一个 .onnx 文件，也不会在你删掉它们之后又冒出来。
:::

## 面板

菜单 **ONNX → 打开面板** 打开运行器面板。自上而下：

| 区域 | 说明 |
|---|---|
| 模型列表 | 扫描到的模型；右侧"扫描"重新读取模型目录 |
| 签名 | 模型的输入输出形状与元素类型——**这是面板最重要的信息** |
| 运行方式 | 按切片（逐平面）或按整卷（分块跑完整个体数据） |
| 平面 | 按切片时的读取平面：XY / XZ / YZ，跟随十字线在该平面上的位置 |
| 结构阈值 | 输出范围里被判为"结构"的比例，预览与应用共用 |
| 输入 / 输出范围 | 原始体素值映到模型输入的线性映射，以及模型输出的量程 |
| 预览 / 应用 | 预览当前切片，或把结果写成掩膜层、整卷结果替换当前数据 |

## 签名决定怎么跑

面板显示的签名不是装饰，它决定运行器怎么做：

| 输入签名 | 行为 |
|---|---|
| `[N,C,H,W]`，H/W 开放（`?`） | 整张切片**一次**推理 |
| `[N,C,H,W]`，H/W 固定 | 自动**分块**切片，再缝合成一张图 |
| `[N,C,D,H,W]` | 自动**分块**整个体数据，块与块保持重叠 |

所以你不需要为"这个模型能不能用"做判断：签名里是 `?` 就是一次跑完，是数字就自动分块，两者对用户是同一个按钮。

::: warning 为什么固定尺寸的模型也能用
固定三个空间轴的模型按自己的分块尺寸推进，因而能用在任意大小的体数据上。相邻分块的读取窗口会重叠几个体素，而每块只写自己的**内部**——距离读边界足够远的那部分。这样每个被写入的体素都是用带完整上下文的数据算出来的，接缝处不会出现明显的断层。
:::

## 阈值是比例，不是绝对值

"结构阈值"是输出范围的比例，解析时以范围**中点**为基准。示例模型这类带状滤波把平坦内容放在中点，所以：

- `0%` 表示"只要不低于平坦水平就算结构"；
- `60%`（默认）表示"比平坦高出 60% 以上才算"；
- 对任何模型，"60%"都是同一层意思。

**预览是对应用的承诺**：面板高亮的体素，和"应用为掩膜"会写进图层的体素，用的是同一个阈值、同一份计算结果。

## 范围映射

模型往往期望归一化输入，而体素是 0–255 或 0–4095 的整数：

- **输入**：填原始最小/最大，运行器把它线性映到模型输入的 0–1。留空表示不做映射（恒等）。
- **输出**：填模型输出的量程。整卷运行时，这个范围被线性铺满目标元素类型的量程，所以整个信号都会被保留，而不是被裁剪。

输出量程来自你的填写而不是测量，这是刻意的：测量意味着再跑一遍整卷，或者物化一份和体数据等大的浮点数据——两者都远贵于填两个数字，而这两个数字面板上本来就显示着。

## 用别的插件调用推理

运行器通过 `layeron.onnx.runner` 这个扩展点发布服务，消费方**不需要**引用 ONNX Runtime：

```csharp
var point = context.Registry.GetPoint<IOnnxRunnerService>(IOnnxRunnerService.PointId);
var runner = point?.Items.FirstOrDefault();
if (runner is null)
    return; // 运行器未安装或未加载

var result = await runner.RunSliceAsync(new OnnxSliceRequest
{
    ModelId = "demo_structure_slice",
    Plane = OnnxSlicePlane.XY,
    Index = services.Volumes.CurrentZ
});
```

两点必须知道：

1. **点是运行器插件自己拥有的**，它卸载时点也消失。把 `null` 当作"运行器未加载"，不要期待一个空点。
2. **必须引用共享契约程序集** `Layeron.Plugins.Onnx.Api`，并且声明 `Private="false"`，否则你看到的是同名但不同类型的接口，服务取到也转不过去，而且不会报错。详见[扩展点](/plugin/extension-points)。

## 设置

设置窗口里的 **ONNX** 页：

| 项 | 说明 |
|---|---|
| 额外模型目录 | 以分号分隔。目录之间靠前者优先；内置示例模型目前先注册，同名文件夹模型不会覆盖它 |

按模型保存的绑定（平面、阈值、范围、运行方式）存在插件数据目录下的 `onnx.settings.json` 里，因此**卸载重载后会保留**。

::: tip 模型放哪里
扫描顺序（靠前者优先）：
1. 设置页里的“额外模型目录”；
2. `<插件安装目录>/models/`；
3. `<工作区>/models/`；
4. `<插件数据目录>/models/`。

内置的两个示例模型不属于上面任何一个目录：它们内嵌在插件里，直接加载自内存。**当前实现会先注册内置示例**，因此同名的文件夹模型不会覆盖内置示例；如果以后要覆盖，先改 `RescanAsync` 的加载顺序。
:::

## 已知限制

- **只支持 CPU 执行。** 面板会显示会话实际采用的 provider。GPU 后端是另装包、另带原生库的事，运行器不替你做这个部署决定。
- **一次只绑一个输入。** 多输入模型需要调用方提供参数张量；原始张量运行会带原因拒绝，而不是跑一半。
- **没有模型链或批处理。**
- **每次启动重新读签名**，不缓存。对一份模型目录来说这个开销可以忽略。
